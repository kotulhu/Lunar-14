# Lunar-14

A retro console quest: you’re a 90s hacker uncovering a government conspiracy. Fictional servers, old-school TUI apps (file manager, mail, chat), humor and easter eggs. Everything is simulated, no real network access.

Учебный консольный эмулятор «Хакер» (C++17). Настоящей сети и файловой системы нет:
всё живёт в памяти и загружается из папки `data/`.

## Утилиты

`help`, `about`, `ls`, `cat`, `cd`, `pwd`, `ping`, `portscan`, `telnet`, `ssh`, `scp`,
`fm`, `mail`, `chat`, `visited`, `downloads`, `run`, `exit`.
Базовые файловые команды (`ls`, `cat`, `cd`, `pwd`), а также `help`, `exit`, `scp`,
`downloads` и `run` доступны на любом хосте. Сетевые утилиты (`ping`, `portscan`, `telnet`,
`ssh`), `fm`, `mail` и `chat` работают там, где хосту разрешён `"commands": "*"`. `portscan` перебирает порты,
`telnet`/`ssh` входят на удалённый хост и добавляют запись в стек сессий (`exit`
возвращает на предыдущий хост). `scp` сохраняет файл в локальное хранилище `downloads/`
вместе с типом и источником; `downloads` показывает список, а `cat downloads/<имя>`
читает только текстовые и data-файлы. На домашнем хосте `downloads/` виден в `ls`,
доступен через `cd downloads` и отображается в `fm`; физически файлы хранятся в
`LocalStorage` и попадают в сохранение. `run <программа> [data-файл]` запускает
игровую программу из `downloads/` или с текущего хоста: сейчас поддержаны `mailsend`
и `.diagnostic`; остальные `program`-файлы отвечают понятной ошибкой. Локальный
`run mailsend leak.txt` выводит получателей и финальные титры из `data/mailsend.json`,
а запуск на `relay-hub` загружает payload для `broadcast`. `fm` — полноэкранный двухпанельный файловый
менеджер на FTXUI. `mail` — полноэкранный почтовый клиент: список писем и предпросмотр,
Enter открывает письмо и помечает его прочитанным. Стартовые письма загружаются из
`data/mail.json`. `chat` — полноэкранный чат: список контактов слева, переписка справа,
строка ввода снизу; собеседники отвечают с задержкой 1-2 секунды. Контакты и переписки
загружаются из `data/chat.json`, правила ответов — из `data/chat_replies.json`,
выбор поставщика ответов — из `data/config.json` (ключ `chat_provider`, пока только
`canned`). Ключ `--unlock-contacts` открывает все контакты. Имена файлов и каталогов,
начинающиеся с `.`, считаются скрытыми: `ls` их не показывает, `ls -a` показывает;
`cat`/`cd` работают с ними по точному имени, а в `fm` их включает клавиша `h`.
`visited` — каталог известных узлов и найденных документов (см. ниже).

Повторный вход на уже посещённый узел (`telnet`/`ssh`) выполняется автоматически:
логин и пароль берутся из сохранённого списка известных узлов, вводить их заново не
нужно. В приложении `visited` тот же список используется для подключения к узлу одним
нажатием.

Запись в виртуальную ФС, экраны `fm`/`mail`/`chat`, прочитанность писем и переписки
живут в текущем запуске. Прогресс сохраняется в файл `save.json` (см. ниже).

## Сохранения

Игра сохраняет состояние в читаемый `save.json` после каждой команды и при выходе
(включая Ctrl+D и Ctrl+C). Совместимость обеспечивает поле `version`: неизвестные
разделы
состояния пропускаются, отсутствующие берутся по умолчанию.

Где лежит `save.json` по умолчанию:

    macOS    ~/Library/Application Support/lunar-14/save.json
    Linux    $XDG_DATA_HOME/lunar-14/save.json или ~/.local/share/lunar-14/save.json
    Windows  %APPDATA%\lunar-14\save.json

При запуске, если сохранение найдено, игра спросит `Saved game found. Continue? [Y/n]`
(Enter или `Y` — продолжить, `N` — новая игра, старое уходит в `save.json.bak`).

Ключи:

    --new             начать новую игру без вопроса (старое сохранение -> save.json.bak)
    --no-save         не читать и не писать сохранение
    --no-delay        отключить все паузы (удобно для проверки)
    --save-dir <путь> своя папка сохранений

При разработке контента удобно запускать с `--no-save` или `--new`.

## Данные

Всё содержимое игры лежит в папке `data/`:

    data/
      world.json            имя домашнего хоста игрока ("player_host")
      hosts/<имя>.json       по одному файлу на хост; имя внутри = имя файла
      texts/                 длинные тексты, на которые ссылаются узлы ФС
      mail.json, chat.json, chat_replies.json, config.json
      events.json            правила-триггеры (см. «События»)
      mail_templates/        шаблоны писем для событий
      credits.json           титры финальной рассылки broadcast
      mailsend.json          получатели и титры локального запуска mailsend
      quest.json             этапы квеста для приложения visited

Узел ФС может быть строкой, массивом строк (склеиваются через `\n`) или объектом:
каталог — объект с дочерними узлами, `{"$file": "путь.txt"}` подставляет содержимое
`data/texts/путь.txt`, а `{"type": "program", "content": "..."}` задаёт тип файла.
Допустимые типы: `text` (по умолчанию), `data`, `program`, `keygen`, `virus`,
`antivirus`. `cat` читает `text` и `data`; `program` запускается через `run`
(для `keygen`, `virus` и `antivirus` обработчиков пока нет).
Системные файлы не живут в JSON: их содержимое вычисляется при чтении
лямбдами в `World::load` (`/var/log/auth.log` на home-pc, `~/.bash_history`,
`/etc/motd` на ftp.jsc-files и ufo-bbs, `/proc/uptime` на relay-hub).
На `dead-host` путь `/var/spool/mail/root` в дереве отсутствует, но `cat`
отвечает ошибкой с телефоном оператора.
По умолчанию папка `data/` ищется рядом с исполняемым файлом;
другую папку можно задать ключом `--data-dir <путь>` (относительный путь считается
от каталога запуска).

## Сюжет

Цепочка квеста: каждый шаг — источник наводки, а не готовый адрес.

    письмо «Ты нам нужен» (ghost)   -> home-pc:/home/hacker/readme.txt
    readme.txt                       -> old-mailserver (203.0.113.5, guest/guest)
    readme.txt                       -> jsc-archive (198.51.100.17, ssh 2222, admin)
    readme.txt                       -> ufo-bbs (203.0.113.33, guest/Houston1969)
    old-mailserver mail.txt          -> пароль admin: город центра управления + год высадки
    jsc-archive docs/mission_7.txt   -> ufo-bbs (адреса ретрансляторов)
    письмо wolf-letter               -> ftp.jsc-files (198.51.100.44)
    ufo-bbs posts/0003.txt           -> agent-pc (203.0.113.77, field/blindspot)
    вход на agent-pc                  -> письмо с ftpuser/files1994 для ftp.jsc-files
    ftp.jsc-files /pub/README.txt     -> relay-hub (operator/relay) + инструкция
    скачивание mailsend и leak.txt    -> письмо «Теперь ты готов»
    локально                          -> run mailsend leak.txt -> получатели + титры
    relay-hub (запасной путь)         -> run mailsend leak.txt -> broadcast

Пароль `Houston1969` один и тот же на `ufo-bbs` и `jsc-archive`, а регистр при
вводе не учитывается. `ufo-bbs` — боковая ветка: там живёт NPC `diona`, её пост
упоминает погасший узел `203.0.113.99` и полевого агента. Этапы в `data/quest.json`
включают файловый сервер в основной путь (`old-mailserver` -> `jsc-archive` ->
`ftp.jsc-files` -> `relay-hub`).

## События

Сигналы входа, чтения файла/письма, скачивания и выполнения команды проверяют
правила из `data/events.json`. Правило содержит `id`, `conditions` (все заданные
условия объединяются через AND), `actions` и `once` (по умолчанию `true`). Условия:
`visited` (массив посещённых хостов), `visited_count`, `downloaded` (имена файлов),
`file_read` (полные пути), `mail_read` (ID шаблонов писем) и `command` (имена команд).
Действия:
`{"mail": "<id>"}` (письмо из шаблона), `{"chat": {"contact": "<id>", "text": "..."}}`
(сообщение в чат) и `{"unlock_contact": "<id>"}`. Сработавшие `once`-правила
запоминаются в сохранении (`state.events`) и повторно не срабатывают. Условие,
пока не выполненное, может быть дополнено следующими сигналами.

Письма берутся из `data/mail_templates/*.json`: каждый файл — массив шаблонов
`id`, `from`, `subject`, `date` и `variants` (случайный вариант при отправке).
В тексте подставляются `{last_host}`, `{visited_count}`, `{player_user}`.
Идентификаторы шаблонов уникальны по всем файлам. Через события приходят и письма
от NPC с наводкой на следующий узел: например, `wolf-letter` после входа на
`jsc-archive` указывает на `ftp.jsc-files`; после чтения его README и скачивания
обоих файлов приходят дальнейшие инструкции. Ошибки данных (неизвестный хост,
шаблон, контакт или действие) останавливают запуск с сообщением с `id` правила.

## Рассылка

Команда `broadcast` помечена как explicitOnly: даже при `"commands": "*"` она
доступна только на хосте, где её имя прямо указано в списке `commands`. По ходу
игры она выводит титры из `data/credits.json` (`delay_ms` и `lines`), подсвечивая
посещённые узлы и их охват `reach` (число компьютеров). После показа титров игра
помечается пройденной (`state.finished` в сохранении), но её можно продолжать.
Локальный `mailsend` — второй финал: он берёт получателей и титры из
`data/mailsend.json` (`recipients`, `credits`, `custom_text`) и тоже выставляет
`state.finished`.
Ключ `--no-delay` отключает все паузы.

## Каталог visited

Команда `visited` доступна на домашнем хосте и открывает номерной каталог: сначала
известные узлы (можно подключиться), затем найденные документы (можно прочитать).
Перед каждым пунктом печатается заголовок вида
`###### дата ##### адрес узла ##### квестовый этап #####`. Дата и этап берутся из
`data/quest.json` на момент появления записи: это именованные этапы квеста, каждый со
своим `when` — как в событиях (`visited`, `visited_count`, `finished`); текущий этап —
последний, чьи условия выполнены. Ввод номера узла подключается к нему через
telnet/ssh с автовходом, ввод номера находки печатает полный текст, `0` — выход.

Документы попадают в каталог из файлов (`cat`), писем и чатов: записывается копия
текста. В каталог идут только тексты, упоминающие другие узлы (имя или IP) — такие
упоминания показываются как «наводки» на ещё не посещённые узлы. Каталог хранится в
сохранении (`state.journal`).

## Сборка

    cmake -B build
    cmake --build build

## Запуск

    ./build/hacker
    ./build/hacker -v
    ./build/hacker --start-host jsc-archive
    ./build/hacker --unlock-contacts
    ./build/hacker --data-dir ../data
    ./build/hacker --new
    ./build/hacker --no-save
    ./build/hacker --no-delay
    ./build/hacker --save-dir /tmp/hacker-save

## Xcode

Открыть `Hacker.xcodeproj`. Проект синхронизирует папку `Hacker` (в ней `src`),
поэтому новые файлы подхватываются автоматически. Заголовки nlohmann/json и FTXUI
и статические библиотеки FTXUI лежат в `build/_deps`, поэтому один раз выполните
`cmake -B build && cmake --build build` из корня проекта (например, перед первой
сборкой в Xcode).

Введите `help`, чтобы увидеть список утилит.
